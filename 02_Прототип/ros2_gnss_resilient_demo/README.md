# Демонстратор устойчивого позиционирования при сбоях GNSS

Лёгкая симуляторная демка сравнивает два способа передавать положение машины диспетчеру. В режиме «Обычный · только GNSS» на карте показывается сырая GNSS-точка: при глушении машина исчезает, при подмене уезжает в ложное место. В режиме «Наше решение · слияние» положение продолжают формировать одометрия, IMU, известные визуальные ориентиры и виртуальные радиомаяки. Истина доступна только испытателю, генераторам датчиков и модулю метрик; алгоритм её не получает.

Текущая версия — чистая симуляция. Интеграция с rosbag, физическим роботом и реальными датчиками в демонстрационный сценарий не входит.

## Быстрый запуск

Требуется Ubuntu 24.04, ROS 2 Jazzy, Python 3.12, NumPy и PyQt5. В проверенной среде они уже установлены. Если Qt отсутствует:

```bash
sudo apt install python3-pyqt5 python3-numpy python3-pytest
```

Из корня проекта:

```bash
./run_demo.sh
```

Скрипт при первом запуске сам выполняет `colcon build --symlink-install`, затем открывает два окна. Если файл потерял исполняемый бит: `chmod +x run_demo.sh`.

Проверка без экрана и экспорт отчёта:

```bash
./run_demo.sh --headless --duration 130 --output run_logs/main
```

Ручная сборка и запуск через ROS:

```bash
source /opt/ros/jazzy/setup.bash
colcon build --packages-select gnss_resilient_demo --symlink-install
source install/setup.bash
ros2 launch gnss_resilient_demo demo.launch.py
```

## Управление

- Красная машина всегда автоматически и стабильно проходит готовый маршрут. Кнопки ручного управления нет: это модель движения испытательного стенда, а не демонстрация автопилота.
- «Старт», «Пауза», «Сброс» и ускорение ×1, ×2, ×5 управляют временем эксперимента. Автоматических отказов нет — все помехи оператор включает вручную.
- В верхней строке выберите режим и одну из четырёх карт: плотный город, поля и посёлок, лесную дорогу или тоннельную развязку.
- «Обычный · только GNSS» показывает только GNSS. Доступны частичное глушение, полное глушение и типовая подмена координат; локальные методы и инфраструктура скрыты.
- «Наше решение · слияние» по умолчанию включает GNSS, камеру, одометрию, IMU и UWB. Каждый источник можно выключить отдельно.
- Фиолетовые UWB-маяки можно перетаскивать мышью; дальности и трилатерация пересчитываются сразу. Кнопка «Зоны UWB» показывает области покрытия. Линия появляется, когда машина находится внутри радиуса маяка; для двумерной позиции нужны минимум три линии с хорошей геометрией. Стены в этой упрощённой модели сигнал не блокируют.
- Контрольная метка становится жёлтой, когда камера действительно наблюдает её. Нужны попадание в сектор обзора, допустимая дальность, видимая лицевая сторона и отсутствие стены. Флажок «Камера включена» включает или исключает этот источник; это не ручное распознавание оператором.
- При выключении камеры её контрольные точки и сектор обзора исчезают. При выключении UWB исчезают маяки, связи и области покрытия.
- В окне «Диспетчер» показывается именно переданная координата, а не истина испытателя.

## Реализовано

- Четыре компактных детализированных JSON-мира: городские кварталы, сельские поля, лесной массив и тоннельный участок. На картах различимы здания, поля, деревья, вода, горные массивы и инфраструктурные зоны.
- Детерминированная модель 50 Гц с независимыми RNG-потоками (`seed=516`).
- Одометрия с масштабом/проскальзыванием; гироскоп IMU с шумом/смещением; GNSS с шумом, потерями, задержкой, скачком и плавным смещением.
- Геометрические камерные привязки с FOV, дальностью, рабочей стороной, окклюзией, пропусками и ошибкой, растущей с геометрией.
- Пятисостояний EKF `[x, y, yaw, speed, gyro_bias]`, Joseph update, контроль возраста и Mahalanobis gating.
- Менеджер доверия сопоставляет источники между собой, учитывает известный риск GNSS в плотной застройке и в реальном времени меняет ковариации и пороги EKF. Источник не включается обратно по одному удачному пакету: нужна серия согласованных данных.
- При потере свежих данных доверие постепенно снижается; при потере всех внешних привязок диспетчер видит предупреждение, а неопределённость растёт.
- Два масштабируемых Qt-окна с базовым шрифтом 28 px и элементами управления высотой от 58 px: цветной полигон с красной машиной и лаконичная карта диспетчера.
- Реальные виртуальные UWB-дальности с шумом/NLOS и позиция по трилатерации при достаточной геометрии.
- CSV `samples.csv`, JSON `summary.json` и `events.json`.
- ROS 2 пакет и launch одной командой. Текущий демонстрационный сценарий остаётся полностью симуляторным и не использует rosbag или физический робот.

## Важные ограничения

- Это демонстрация на синтетических данных, не подтверждение точности реального оборудования и не сертифицированная система безопасности.
- Обычный EKF не гарантирует обнаружение плавного спуфинга. Без независимой привязки согласованная ложная траектория может пройти проверку.
- Камера — геометрическая модель известных меток; распознавание ArUco/AprilTag не моделируется.
- Решение предназначено для известных и, при необходимости, оборудованных участков, а не для любой дороги без инфраструктуры.
- UWB здесь — упрощённая геометрическая модель виртуальных маяков, а не физическая модель радиораспространения.
- Число «доверие 0…1» — внутренняя текущая оценка согласованности и свежести, а не вероятность безопасности и не заявленная точность датчика.
