# Архитектура и границы данных

```text
WorldModel (истина) ──┬──> SensorSuite ──> ReliabilityManager ──> NavigationEKF
                      │                         │                     │
                      └──> ExperimentEvaluator <─┴── FilterSnapshot ─────────┘
                               │
                               └──> GUI / CSV / JSON
```

`NavigationEKF` и `ReliabilityManager` получают только измерения, прогноз и известный тип местности. У них нет ссылки на `WorldModel`, поля истины или флага «спуфинг». Оператор вводит все отказы вручную, а GUI отдельно показывает включённое воздействие и решение алгоритма.

Симуляционное время движется фиксированными шагами 0,02 с. Скорость GUI меняет число шагов на секунду, а не размер шага. Отдельные RNG-потоки одометрии, IMU, GNSS, камеры и UWB создаются из seed 516. UWB-позиция вычисляется из виртуальных дальностей минимум до трёх маяков; при плохой геометрии полноценная координата не создаётся.

Диспетчерский выход имеет два режима: сырой GNSS без проверки либо результат устойчивого слияния. Переключение режима перезапускает детерминированный эксперимент с тем же seed.

## Реальный режим

```text
Frob /odometry/filtered ── twist ──> prediction
/camera/global_pose ───────────────> global correction
/gnss/global_pose ─────────────────> global correction
                                      │
                                      └──> /resilient_nav/odometry
```

Адаптер намеренно не подписывается одновременно на готовую `/odometry/filtered` и её исходные `/odom` + `/imu/mpu6050`: это было бы двойным учётом коррелированных данных. Предлагаемая TF-схема — `map → odom → base_footprint`; перед публикацией `map → odom` нужно определить единственного владельца. Прототип TF по умолчанию не публикует.

Реальная камера должна выдавать `PoseWithCovarianceStamped` после калибровки intrinsics, задания размера/позы метки на карте и transform `camera → base_footprint`. Замена геометрического симулятора на AprilTag/Aruco не требует изменения EKF.
